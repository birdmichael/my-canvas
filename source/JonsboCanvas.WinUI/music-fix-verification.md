# 网易云同步与音乐帧率修复记录

## 已确认的根因

1. 本机网易云主进程启动参数为 `--orpheus-startup=autorun`，没有配置中的 `--remote-debugging-port=38476`。
2. `127.0.0.1:38476` 没有监听端口，因此 WinUI 只能从网易云缓存判断歌曲，不能获得真实播放进度、暂停状态和歌词时间。
3. WinUI 的 `DispatcherTimer` 原为 100 ms，任何大于 10 FPS 的设置都会被硬性封顶。
4. 每个本地预览帧原先会在 UI 线程编码成 PNG，造成明显交互卡顿。
5. 帧间隔原先从“上一帧完成”开始计算，渲染耗时会叠加在目标间隔上；20 FPS 在测试中只有约 14.7 FPS。
6. CDP 位置推算最多只外推 1.2 秒，播放事件稍有间隔就会造成进度和唱片动画停顿。
7. 固定 Runtime binding 在 Jonsbo Canvas 重启后仍指向旧 CDP 会话，表现为“已连接”但收不到事件。
8. 实时事件暂时没有歌曲 ID 时扫描最新 `.uc` 缓存，会把另一首缓存歌曲的标题和歌词混入当前播放状态。

## 修复内容

- 音乐页新增“启用同步”状态按钮；检测到网易云已运行但没有实时通道时，明确提示并经用户确认后正常重启网易云。
- 重启时加入仅监听 `127.0.0.1` 的调试端口；不强杀未正常退出的网易云进程。
- 调度器提高到 10 ms，仅由每个模式的目标间隔决定是否生成帧。
- 帧率改为按帧开始时间调度，避免把渲染耗时重复加到目标间隔。
- WinUI 本地预览改用 `WriteableBitmap` 直接复制 BGRA 像素，不再逐帧编码 PNG。
- 桌面预览与 USB 输出都按用户选择的 5–20 FPS 渲染，直接像素上传避免预览反向限制设备。
- 实时播放时每帧刷新位置快照；CDP 根据播放/暂停事件连续外推位置，不再在 1.2 秒后冻结。
- 音乐页新增“实际 FPS”读数，让设置是否生效可以直接验证。
- 帧率控制改成可直接点选的 5/8/10/15/20 FPS 离散档位，避免滑杆难以精确选择。
- 禁用 CEF DevTools 不兼容的 WebSocket 保活帧，消除原先每 15 秒一次的实时通道断线。
- 同步协议按 Taskbar-Lyrics（MIT）和 LibSongInfo 的原生播放器事件实现校对，只监听 load/progress/state/end；删除猜测的 seek/position 事件。
- 歌曲 ID、秒数和歌词只使用同一条实时事件流；删除会把其他缓存歌曲混进来的 `.uc` 最新文件兜底。
- 每次 CDP 连接使用唯一 Runtime binding，页面中的事件监听器通过可热切换分发器转交给当前会话；Jonsbo Canvas 单独重启或 WebSocket 重连后不会继续调用失效的旧绑定。
- 歌词使用 Taskbar-Lyrics 相同的 `song/lyric/v1` 时间轴，同时解析当前 JSONL 富歌词和旧 `[mm:ss]` LRC；首次请求为空时自动重试。
- 音乐画面显示上一行、当前行、下一行，并在换行时进行明显的纵向滚动过渡。

## 自动化验证

- 编译：0 errors。
- UI Automation 设为 5 FPS：实际读数约 4.9 FPS。
- UI Automation 设为 20 FPS：在另一份 JonsboCanvas 实例仍运行的并发环境下，实际读数约 16.3 FPS，设置变化已经真实作用于渲染循环，不再被 10 FPS 定时器封顶。
- 合成原生事件链路：固定歌曲 ID `362937` 从 `199.694s` 递增，歌词按 LRC 依次切换为“紧紧埋藏在心底”“你就像烟火的神秘 那么神秘”“风随着你若即若离”，全程未混入缓存歌曲。
- 重启接管测试：保留网易云页面和已注册监听器，销毁第一条桥接后由第二条唯一 binding 接管；歌曲 ID、进度和歌词继续更新。
- 帧率下拉框当前档位可直接选择，控件可键盘聚焦。

## 真机验证边界

没有在未确认的情况下关闭用户当前正在播放的网易云，因此“重启并同步”最终连接需要用户在修复版中点击一次并确认。实体 USB 屏幕发送逻辑未被替换。
