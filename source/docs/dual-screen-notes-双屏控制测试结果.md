# 双屏控制测试结果

测试日期：2026-10-04（北京时间）。

结论：独立测试程序已分别控制1920×462长条屏和480×480方屏，并同时更新不同画面。用户通过实机观察确认“现在两块都正常”。

## 已验证的连接方式

| 屏幕 | 连接方式 | 最终画面处理 |
|---|---|---|
| 1920×462长条屏 | COM3，USB VID_33C3 / PID_F101；串口传输JPEG | 1920×462画布顺时针旋转270°，以462×1920传输 |
| 480×480方屏 | MS USB Display，VID_345F / PID_9132 / MI_03；显示SDK | 追加480×480模式，选择480×480 @ 60Hz；画布顺时针旋转90° |

## 测试证据

- 长条屏设备查询返回原生尺寸462×1920、刷新参数60。
- 方屏SDK启动、设置480×480模式、逐帧发送及停止均返回0。
- 最后一轮约40秒：前5秒更新方屏，接着5秒更新长条屏，最后约30秒两块同时更新。
- 最后一轮每块发送36帧，两块显示不同底色、文字、边框和递增编号；日志没有发送异常。
- 用户确认两块屏幕的显示方向与更新均正常。
- 测试结束释放串口与SDK，重新启动JONSBO-AIO。

最初方屏只显示部分画面，原因是SDK仍使用默认800×600模式。设置EDID追加模式（Mode=2）后，SDK明确报告480×480可用模式，问题解决。两块屏幕的旋转方向已根据实机反馈校正。

## 后续开发依据

两块屏幕需要分别使用串口JPEG与USB显示SDK两种发送方式，共用数据采集但独立渲染。测试源码为独立编写，方屏调用电脑已安装的显示SDK。原项目的单屏控制代码不能直接覆盖两种设备。

本次验证的是约每秒1次的画面更新、独立控制和短时同时运行。60Hz为设备模式参数，并非本次测试达到的发送帧率；高帧率动画、长时间运行、热插拔及休眠恢复尚未测试。

文件：`DualScreenTest.cs`为最终测试源码；`dual-screen-test.log`为最后一轮完整日志。运行测试需要现有驱动及显示SDK，且JONSBO-AIO需先释放设备。
